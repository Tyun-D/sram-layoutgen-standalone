| RowPeripheryPhysicalGenerator | physical_generator | Compose decoder stages and wordline driver structures into a row-pitch-aligned row periphery region. | CanonicalSramParameterModel; RowPathIntent; PhysicalModuleRegistry | structure_complete_module_layouts; placement_ready_module_geometry; pitch_aligned_boundaries | True | True | Adapt candidate module metadata and selected import/write utilities; do not reuse legacy placement strategy. | True | OpenRAM treats address decode and wordline drive as one explicit row-path module boundary. | Allow reuse of existing candidate row logic blocks but move pitch alignment ownership into the new generator. | P0 | Medium; row-pitch mismatch would break later wordline routing. | Define array-facing anchors and row expansion contract for decoder-to-driver composition. |
| ColumnPeripheryPhysicalGenerator | physical_generator | Compose precharge, column mux, sense amp, and write driver structures into a column-pitch-aligned column periphery region. | CanonicalSramParameterModel; ColumnPathIntent; PhysicalModuleRegistry | structure_complete_module_layouts; placement_ready_module_geometry; pitch_aligned_boundaries | True | True | Reuse hardmacro wrapper metadata for column_mux, sense_amp, write_driver, and precharge. | True | OpenRAM stacks column path blocks in a deterministic order driven by column pitch and mux topology. | Preserve words_per_row and column_mux_ratio as generator inputs even when the baseline config is mux-free. | P0 | Medium; wrapper width alone cannot guarantee column-pitch ownership. | Define block order, bit-slice ownership, and optional mux insertion contract. |
| ControlPeripheryPhysicalGenerator | physical_generator | Compose control logic, delay chain, enable paths, and DFF rows into a peripheral control region with explicit bus ownership. | CanonicalSramParameterModel; ControlPathIntent; PhysicalModuleRegistry | structure_complete_module_layouts; placement_ready_module_geometry; pitch_aligned_boundaries | True | True | Adapt candidate control path metadata and selected sanity checks from top_level_validation.py. | True | OpenRAM treats control logic and replica delay semantics as structured periphery objects, not loose modules. | Preserve OpenYield-specific control net names and delay/replica semantics as explicit outputs for later routing. | P1 | Medium; control buses can be semantically correct but physically unreachable without region planning. | Define control cluster grouping and exported control spine anchor points. |
| SRAMTopologyFloorplanner | floorplan | Own the SRAM-specific region arrangement for array, row periphery, column periphery, control periphery, and power reservations. | CanonicalSramParameterModel; ArrayTopologyContract; RowPathIntent; ColumnPathIntent; ControlPathIntent; PhysicalModuleRegistry | array_region; row_periphery_region; column_periphery_region; control_region; power_region; top_bbox; placement_plan | True | True | Adapt only low-level GDS import/write utilities from top_level_assembly.py; do not reuse its candidate-only placement strategy. | True | OpenRAM bank and sram_1bank place major regions with SRAM-specific quadrants and channels. | Keep the topology array-centric and single-bank, avoiding OpenRAM multi-bank/global-state complexity. | P0 | High; poor region ownership would force later routers to become ad hoc patch layers. | Define region adjacency, array-facing edges, reserved channels, and top bbox computation policy. |
| WordlineRouter | router | Connect wordline driver outputs to one physical WL per array row with row-pitch alignment. | placement_plan; RowPathIntent; CanonicalSramParameterModel | wordline_routes | False | True | Potentially reuse future primitive geometry emitters and validation hooks; no existing router should be treated as complete. | True | OpenRAM keeps decoder-to-driver and driver-to-WL routing explicit and row aligned. | Route only deterministic SRAM wordline patterns; avoid a generic router. | P2 | Medium; routing policy must align with exported row pitch from the array generator. | Define row-track reservation and array-edge handoff geometry. |
| BitlineRouter | router | Connect array BL/BR rails to precharge, optional column mux, sense amp, and write driver while preserving column pitch. | placement_plan; ColumnPathIntent; CanonicalSramParameterModel | bitline_routes | False | True | Reuse hardmacro pin metadata and future GDS primitive backend only. | True | OpenRAM routes bitlines and mux-dependent column-path connectivity explicitly from topology. | Support mux-free baseline and later mux-enabled configs through parameterized column routing ownership. | P2 | High; column routing topology changes with mux ratio and directly impacts sense/write ownership. | Define array-edge escape pins and per-bit routing templates for mux-free and muxed cases. |
| ControlRouter | router | Distribute precharge_en, sense_en, write_en, wordline_en, clk, gated_clk, and replica timing nets across periphery regions. | placement_plan; ControlPathIntent; openyield_net_to_layout_role_map.csv | control_routes | False | True | Reuse net role metadata and selected validation report patterns. | True | OpenRAM models control as structured buses and delay-driven periphery routes. | Preserve OpenYield net names and semantic bus ownership in the route model for R5 validation. | P2 | Medium; semantic collapse of control and replica nets would undermine later validation. | Define control spine anchors, route classes, and timing/replica route tags. |
| PowerPlanner | power | Plan VDD/GND ownership, rail stitching, regional distribution, and top-level power export for array and periphery regions. | placement_plan; openyield_power_intent.json; PhysicalModuleRegistry | power_routes; power_region; top_level_power_pins | False | True | Adapt rail metadata, hierarchy export backend, and validation evidence framework. | True | OpenRAM treats power export as a layered routing problem instead of pin copying. | Use existing module rail metadata as input hints, but require generator-owned top-level stitching in R4. | P2 | High; power continuity is a core boundary between prototype assembly and a real SRAM generator. | Define region-level rail entry sides, stitch points, and VDD/GND perimeter pin ownership. |
| PinLabelExporter | export | Export top-level pin shapes, labels, and naming-consistent IO/power metadata from routed geometry. | placement_plan; openyield_pin_intent.json; wordline_routes; bitline_routes; control_routes; power_routes | top_level_pin_shapes; top_level_labels; pin_export_report | False | True | Reuse custom GDS writer label capability and existing pin audit/report patterns. | True | OpenRAM derives pin exports from layout-owned geometry and naming consistency rules. | Use OpenYield addr/din/dout/control naming exactly as defined in R1 intent. | P2 | Medium; pin naming drift would break later LEF/LVS correlation. | Define top-level pin classes, legal placement edges, and label naming policy. |
